# 任务列表内嵌文件列表 PRD（维护版）

> 状态：当前实现说明，按 2.2.5 代码与回归测试核对，2026-10-24。
>
> 本文是任务列表文件列表的唯一产品规范。历史设计稿中“仅下载页”“每秒完整拉取”等表述不是当前行为。

## 0. 维护决策原则

任务列表应稳定、直观，展示功能不能改变下载行为，也不能明显增加 aria2 负载。

- 优先修复高概率问题、会显示错误文件树或冻结刷新的问题，以及改动小、不改变产品语义的问题。
- 对极端时序、断线或多标签页才会触发的边界，先如实记录；不为假设场景增加常驻请求或复杂状态。

## 1. 目标与范围

用户无需逐个进入任务详情，就能在任务列表中查看每个任务的目录、文件大小和单文件进度。

适用于三个任务列表页：`/downloading`（正在下载）、`/waiting`（等待／暂停）、`/stopped`（已完成、出错或已停止）。

这是一个共享的只读展示模式，不改变 aria2 的下载、文件选择或任务状态，也不影响任务详情页。

不在范围内：按文件名全局搜索、单任务独立开关、分页或虚拟滚动、文件数量上限、在列表中修改文件选择。文件选择只能在任务详情页修改。

“正在下载”页开启文件列表后，还会显示 BT 小文件批量过滤操作栏，因为它依赖这里的完整文件数据。该操作栏的行为见 [BT 小文件过滤 PRD](bt-small-file-filter.md) 第 4 节。

## 2. 用户体验

### 入口与持久化

- 三个任务列表页的顶部工具栏在“帮助”后显示同一个“文件（Files）”开关，其他页面不显示。
- 开关默认关闭，由一个持久化设置 `showFileListInTaskListPage` 控制三个页面。
- 升级兼容：首次读取新设置时，若只存在旧设置 `showFileListInDownloadingPage`，沿用其布尔值并写入新设置；之后以新设置为准，显式的 `false` 也保留。
- 切换开关会立即刷新当前列表；切换页面、刷新浏览器或重新打开后保持该选择。

### 展示与交互

- 只有任务带有非空 `files` 时，才在任务摘要下方显示内嵌面板；没有文件数据时不显示空面板。
- 单层任务显示文件名、进度条及百分比、文件大小；多目录 BitTorrent 任务显示目录树。
- 文件和目录复选框一律禁用，只用来显示选择状态；目录可以展开和折叠。
- 搜索和任务排序以任务为单位，面板随所属任务一起隐藏或移动。
- 单层任务可按名称、进度、大小排序；多目录任务保持树形顺序。文件排序使用全局 `fileListDisplayOrder`，与任务详情页共用。
- 文件区域阻止点击冒泡，不会误选外层任务、触发右键菜单或进入详情页。
- BT 小文件过滤的“过滤中”徽标显示在任务名右侧，与文件面板互不影响。

### 目录折叠

折叠状态按 `gid + 目录路径` 隔离，折叠父目录会递归隐藏子树。状态只保留在当前列表页：任务离开列表即清除；刷新页面、切换路由或重新打开后不恢复。

## 3. 数据与刷新契约

在实时性、aria2 负载和浏览器 DOM 成本之间保持以下平衡：

| 页面 | 首次打开、开启开关或结构变化时 | 稳定后 | 新鲜度 |
| --- | --- | --- | --- |
| `/downloading` | 请求完整字段 | 任务摘要按用户设置的间隔请求基础字段；文件明细最多每 5 秒请求一次完整字段 | 摘要默认约 1 秒；单文件进度约 5 秒 |
| `/waiting` | 请求完整字段 | 只做基础字段增量刷新 | 文件列表为最近一次完整读取的结果 |
| `/stopped` | 请求完整字段 | 只做基础字段增量刷新 | 同上 |

补充约束：

- 完整字段 = 基础字段 + `dir`、`files`、`bittorrent`、`infoHash`、`following`。前三项用于文件视图和相对路径；`infoHash` 和 `following` 供 BT 过滤预览与恢复使用，不能因为列表不显示就删掉。所有任务在一次列表请求中返回，不逐个任务调用 `tellStatus`。
- 基础响应只更新任务摘要，保留上一次完整响应的文件树和任务名；完整响应才刷新单文件进度。
- 基础响应合并前，先清除校验相关字段，避免“正在校验”状态在校验结束后残留。
- 基础响应发现任务集合或顺序与当前列表不一致时，下一轮改为完整请求，不把旧文件树套到新任务上。
- 系统时钟回拨时，文件明细立即视为到期。
- 完整请求在途时，基础请求不能越过它。超过 30 秒仍无回包时解除该保护，避免永久冻结。请求序号和模式代次会丢弃过期响应。
- 刷新间隔设为 `0` 时，只做初次读取和用户触发的读取。BT 批量过滤完成后仍会主动做一次完整读取，用于确认新选择。

## 4. 文件与目录数据模型

`aria2TaskService.processDownloadTask()` 把 aria2 原始任务转换为视图数据：

- 文件的 `index`、`length`、`completedLength` 转为数字，并派生 `fileName`、`selected` 和 `completePercent`。
- 长度为 `0` 的文件：任务已完成时显示 `100%`，否则显示 `0%`，不能出现 `NaN`。
- 只有多目录 BitTorrent 任务构建虚拟目录节点。相对路径会去掉下载目录和 torrent 根目录，兼容 Windows 路径分隔符。目录字典不继承原型，目录名为 `constructor` 或 `__proto__` 时也能正确显示。
- 每次完整处理前，先删除上一轮的虚拟节点，再用真实 `files` 重建。

最重要的不变量：**完整响应重建文件树，基础响应保留文件树。**

## 5. 视觉与无障碍

- 内嵌面板是所属任务行的一部分：完整边框、左侧强调线、独立表头和行分隔。不把任务列表改为卡片流。
- 浅色和深色主题都覆盖面板、表头、行悬停和外层斑马纹；内层文件行不继承外层背景。
- 只读复选框明显弱化，目录展开图标保持可见、可点击。
- 窄屏下左右内缩为 5px，沿用 Bootstrap 列布局，不产生横向滚动。
- 任务行按 GID 复用 DOM，真实文件按索引、虚拟目录按路径复用，刷新时不整页重建。

## 7. 验收重点

修改本功能时至少保持：

1. 三个任务列表页共用一个默认关闭、可迁移的开关。
2. 下载页不每秒完整拉取所有文件；等待页和停止页稳定后不周期性完整拉取。
3. 快速切换、乱序回包、完整回包丢失、时钟回拨、同长度 GID 替换，都不会显示错误的文件树或永久冻结刷新。
4. 目录树不重复，折叠状态按任务隔离；任务操作、搜索、排序、拖动和详情入口不回归。
5. 浅色、深色和窄屏下面板可读、不溢出。

先运行 `node test/task-list-file-list.test.js`，再按 [AGENTS.md](../../AGENTS.md) 的风险矩阵运行 `npm test` 和构建；模板或样式改动需检查受影响的界面状态。
